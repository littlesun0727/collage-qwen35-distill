# 本地可视化标注台

默认地址为 http://127.0.0.1:8765。请自行提供已准备好的标注数据集，公开仓库不包含私人图片和 GT。

也可以在仓库根目录运行：

```powershell
python -m annotation.server --dataset data/annotations --port 8765
```

无需安装前端依赖；使用现有 Python、Pillow 和仓库的结构校验器。数据和编辑都在本机，不调用模型 API。

## 怎么审核

1. 左侧选模板，右侧先看“核查提示”。点“定位到图中”高亮具体元素，点“修改元素”进入编辑。
2. 点击框选中元素；拖框移动，拉角点或边缘调整大小。漏了元素，点“画框”后拖出新框。右侧修改中文类别和内容说明。
3. 相框通过勾选照片建立关联；连续出框前景通过下拉选择来源。删除对象会同步清理引用和遮挡对；如果剩余相框失去照片关联，保存前需补选。
4. 在“遮挡与层级”里比较两个元素，选择 A/B 哪个在上、互不遮挡或看不清。确定上下关系后同步调整图层，防止形成循环。框相交只用于提出候选，不会自动当作真实遮挡。
5. 在“完成审核”逐项确认。可以随时“只保存进度”；七项确认完成后，才能标记本张已审核并进入下一张。

快捷键：V 选择、N 新增、空格按住看原图、Ctrl S 保存、Ctrl Z 撤销、Ctrl Shift Z 重做。
“对比初始框”显示来源快照中的白色虚线框；修改框不会改变原图像素，也不会重新合成模板。

## 潜在问题的含义

- 红色：可确定的结构规则错误，如无效关联、出框前景排在来源下面、同一照片绑定多个框体。
- 黄色：几何或描述疑点，如同类框几乎重合、相框与照片不相交、描边与框体口径可能混淆。点击“已核对，保留”可确认当前结果；相关元素发生变化后会重新提示。
- 蓝色：依据当前标注提出的核查重点，如连续出框是否真的属于同一张照片、多窗口绑定是否正确、被遮挡照片是否保留完整范围、全幅摄影底图是否连续。

这些是可解释的规则与审核引导，不是另一个视觉模型的判定。不能自动找出所有漏标、框偏差或分类错误；没有提示也需要看图检查。当前没有在线模型审图步骤。

## 保存与恢复

- 修改写入对应 case 的 `structure.json`、`review.json`，以及根目录 `occlusions.jsonl`。
- 原图、`teacher.structure.json`、`assistant.structure.json` 均只读。
- 每次保存前，在 `.annotation-history/<样本ID>/` 记录原结构、审核状态和遮挡标注。页面可恢复历史为草稿，再手动保存。
- 每个样本带版本指纹，另一个页面或编辑器先修改后，旧页面保存会被拒绝，避免覆盖别人的修改。单次保存的写入异常会回滚，历史快照可用于恢复。
- 浏览器会暂存未保存草稿；重新打开时可选择恢复。切换图片时会先尝试保存，失败则保留当前页。
- “遮挡对已确认”未勾选时，所选关系保存在 `review.json` 的 `occlusion_draft` 中，正式侧文件仍为 null。勾选后写入明确的 pairs；空数组表示已检查、无适用遮挡对。
- 平台实时读取审核状态；准备时生成的 manifest 统计、review.csv 和静态预览不会自动刷新。正式冻结 GT 和刷新统计仍是独立步骤，不会因点了保存而把整套数据宣称为审核完成。

公开版使用上述 Python 命令在前台启动，Ctrl+C 停止。远端使用时由你自己的端口转发访问，不对外公开标注服务。

## 验证

`tests/test_annotation.py` 验证保存、来源不变、备份、版本冲突、遮挡侧文件、审核门槛、错误回滚和本地接口。
`tests/test_annotation_browser.py` 使用临时数据，在真实 Chrome 中完成拖框、缩放框、新建、删除/撤销、关联、遮挡确认、保存和历史恢复；不会改正式数据。

```powershell
python -m pytest tests/test_annotation.py tests/test_annotation_browser.py tests/test_eval.py -q
```

浏览器集成测试需要 Playwright 和本机 Chrome；不满足条件时跳过该项。标注台本身不依赖 Playwright。
